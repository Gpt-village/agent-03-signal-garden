# Signal Garden playtest protocol

This protocol is for evaluating **The Signal Garden** as an interactive world, not for finding a single optimal strategy.

## General observations to record

For each run, note:

- seed;
- input method (mouse/touch/keyboard);
- cycles played;
- topology built;
- dominant island roles;
- macro-climates reached;
- resident species / symbioses observed;
- phenomena triggered;
- whether the player understood why a consequence happened;
- moments that felt surprising versus arbitrary;
- any action whose consequence was hard to perceive.

Use **Copy summary** when possible. Do not include private field-log/Chronicle text unless the tester deliberately chooses to quote it.

## Scenario A — keyboard-only first contact

Goal: prove the world is playable without canvas clicking.

1. Use keys 1–4 to inspect starting islands.
2. Use N/O/D to change signal mode.
3. Use Enter or the native Apply button to act.
4. Use Connect via keyboard as a two-step source → target operation.
5. Advance at least two cycles.

Observe:

- focus visibility;
- selection clarity;
- Connect state clarity;
- whether native focused buttons still behave normally;
- whether any information exists only in animation.

## Scenario B — topology ecology

Goal: make topology itself matter.

Try to create, separately:

- a hub with 3+ edges → **Relay Crown**;
- one connected ring → **Loopmoss**;
- one connected simple corridor → **Threadfin**.

Then heavily use one route, cut it, and look for **Ghost Reed**.

Observe whether the resident appears close enough to the topology change that the relationship is understandable.

## Scenario C — mixed bridge symbiosis

Goal: test interaction between island role and mature route history.

Create mature bridges between:

- grove + archive → **Scribevine**;
- grove + fold → **Glass Mycelium**;
- archive + fold → **Dreamwire**.

Harder experiment: sustain all three simultaneously.

Observe whether role changes make symbioses feel alive or frustratingly unstable.

## Scenario D — climate persistence

Goal: test archipelago-scale feedback.

Hold each macro-climate long enough to identify its feel:

- Verdant Air;
- Echo Haze;
- Fracture Weather;
- Braided Sky.

Then hold one climate for at least three consecutive cycles to trigger its phenomenon:

- Seed Rain;
- Memory Dew;
- Parallax Bloom;
- Confluence Pulse.

Observe:

- whether the 3-cycle streak is legible;
- whether the phenomenon effect is noticeable without reading the Chronicle;
- whether reduced-motion presentation still communicates it;
- whether sustaining one climate is interesting rather than repetitive.

## Scenario E — world growth

Goal: test progression from four to seven islands.

1. Build resonance.
2. Germinate one island.
3. Compare a seasonal/climate-biased birth with the starting islands.
4. Integrate the new island into the migration network.
5. If practical, fill all seven sites.

Observe whether new land changes strategy or merely adds more nodes.

## Scenario F — specimen exchange

Goal: verify that sharing transfers world state without transferring private/local prose.

1. Build a recognizable topology.
2. Accumulate route memory.
3. Add at least one glyph.
4. Trigger or record climate state if practical.
5. Copy an SG1 specimen.
6. Reset/open another local garden and import it.

Confirm:

- traits;
- topology;
- route memory;
- glyphs;
- climate/phenomenon bounded state.

Also confirm that rolling field-log and Chronicle prose did not transfer.

## Scenario G — long-history garden

Goal: see whether accumulated history remains readable.

Play for 15+ cycles with at least two rewires and several role changes.

Observe:

- route scar readability;
- Chronicle usefulness;
- discovery list overload;
- HUD crowding;
- whether the garden develops an interpretable identity.

## Acceptance priorities

A new feature is valuable when it improves at least one of:

1. **causal clarity** — players understand why the garden changed;
2. **meaningful choice** — different actions/networks produce different futures;
3. **world identity** — a garden develops a history worth distinguishing from another seed/specimen;
4. **accessibility** — required information/action is available without relying on a single modality;
5. **finishability** — complexity stays understandable enough to explore.

Prefer fixing a weak existing loop over adding another disconnected subsystem.
